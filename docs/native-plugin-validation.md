# 最小原生插件验证（后置，尚未执行）

前置条件：真实任务评估已形成可审查结论，确认该技能值得继续使用，并明确要核实的安装/维护需求。当前先做技能效果，本文只是限定后续实验范围。

进入该阶段时核对本机版本与官方文档。用一个已有技能和一个最小原生插件格式，在隔离本地目录验证，不搭建公共 marketplace，不上传、不增加账号/凭证，不同时维护另一份核心业务指令。

最小验收仅包含：

1. 本机实际支持的原生插件格式及本地发现方式。
2. 能否发现并显式调用这个技能；名称、来源和版本能否清楚识别。
3. 一个内容变更在新会话中的实际加载行为；原有安装是否受影响、是否出现同名歧义。
4. 恢复或移除本实验配置，确认没有残留同名注册。只操作本次实验自己创建的目录与配置。
5. 将当前确实需要的项目隔离、版本固定或恢复能力列为“已覆盖/有证据的缺口/未知”，不预设必须自建补齐。

实验的发现与调用证据、清理结果分别记录。若需要写真实全局宿主配置或安装用户级技能，先形成具体范围与回退方案，按既有授权边界处理。原生宿主管理的缓存不由自制脚本直接覆盖。

本阶段不验证通用分发、第三方依赖管理、签名体系、多宿主支持或自动更新。发现一个缺口不自动恢复整个自建运行时路线。
