# 使用技能

仓库作者源统一使用 `af-` 前缀，每个技能可独立读取完整文件夹使用。当前命名规则和边界见 [ADR 0007](decisions/0007-af-prefix-and-skill-creator.md)。

## 选择入口

| 当前目的 | 使用入口 |
| --- | --- |
| 产品如何工作、业务状态与源码实现、架构取舍 | [af-product-deep-dive](../skills/af-product-deep-dive/SKILL.md) |
| 产品方向、需求机会、竞品启发、方案选择 | [af-product-intelligence](../skills/af-product-intelligence/SKILL.md) |
| 技能必要性判断、设计、创建、改进、审查、评估与维护 | [af-skill-creator](../skills/af-skill-creator/SKILL.md) |
| 新系统架构、现有方案评审、技术选型、流程细化与兼容迁移 | [af-architecture-design](../skills/af-architecture-design/SKILL.md) |

可直接指定作者源：“使用 `skills/af-product-deep-dive/SKILL.md`，分析给定仓库的任务执行与恢复机制，提供文件/符号依据，环境允许时做局部验证。”仅有官网材料时要求区分来源说法与推断，不猜内部实现。

技能建设可说：“使用 `skills/af-skill-creator/SKILL.md`，根据这些重复任务判断是否值得技能化；若值得，在本仓库创建最小完整技能并验证。”只要方案则明确不写文件；已有明确创建授权时不要求额外重复审批。

## 按任务使用

架构任务可说：“使用 `skills/af-architecture-design/SKILL.md`，根据已有需求、技术栈与团队约束，比较可行方案并细化模块、接口、失败恢复和验收任务。”也可只评审一条链路或一个技术决定，无需先填写模式表单。选择已有产品/方向与研究已有实现仍分别由产品技能负责；新技能不替代代码实现或生产运维。

af-architecture-design 初始阶段只在作者源实现。2026-10-25 用户随后明确授权备份、安装、核对加载并提交推送：现已完整安装到用户级 `.agents/skills/af-architecture-design/`，18 个文件清单与 SHA-256 一致、14 条内部链接有效。当前桌面同版加载器在项目和用户目录均返回 user、enabled=true、无错误；可使用 `$af-architecture-design`。桌面 UI/当前会话刷新和自动触发未实测，仍可通过上述作者源路径显式读取。下文三个既有技能的历史同步记录保留原范围。

产品研究可以直接问局部机制或条件比较，无需每次填写简报。具体产品研究按请求选择快速扫描、深度剖析、技术逆向或专项研究；方向研究围绕真实需求、最强替代和认知增量。复杂任务提供当前目的、已有认识和材料，关键歧义才澄清。

判断是否自建时说明任务和约束，研究会检验现有产品、工具组合或人工流程；新证据可更新原判断。混合任务复用有来源和边界的成果，不自动跨技能调度。默认会话交付，保存、执行和外部操作服从当前授权。

技能建设先比较现有能力、短提示、文档或脚本。五种工作模式按请求选择，Spec 只在创建或明显改变职责时使用，不强制全阶段、模板或目录。它不把普通业务任务改成技能项目，也不接管两个产品技能的职责。

## 本机使用副本与兼容性

2026-10-25 用户后续授权后，重新检查了用户级 `.agents/skills/`、`.codex/skills/` 与本项目的对应目录。两个旧名副本各 22 个文件，无额外文件或独立修改，新名目标未占用。先备份并核验旧副本、93 个仓库文件、补丁、索引和历史 bundle，再将两个旧目录迁移为 `af-product-intelligence`、`af-product-deep-dive`，安装 `af-skill-creator`。

迁移时三个用户级副本分别有 22、22、10 个文件，完整清单、SHA-256、63 条内部链接与入口格式核对通过。旧无前缀目录已按授权迁移，原内容保存在忽略备份中；当时本机配置未发现绑定这些旧名的配置项，没有改动宿主配置。以后直接使用三个新的 `$af-...` 名称，其他项目或历史请求中的旧名引用不会自动改写。

AF Skill Quality Loop 的初始实施仅修改作者源；用户随后明确授权备份、同步、核对宿主加载并提交推送。同步前工作区与上一轮审阅快照一致，三个使用副本无独立修改或额外文件。备份并校验 93 个仓库文件、54 个使用副本、补丁、索引和 Git 历史后，仅更新 5 个有差异的技能文件；全部 54 个文件清单与 SHA-256 一致，64 条内部链接有效。同版宿主加载器再次在项目及用户目录识别三个启用技能，无错误；未修改宿主配置或启动常驻服务。备份与远端结果见验证报告，今后同步仍需任务授权。

同一桌面宿主二进制 `0.164.0-alpha.11.1` 的临时 stdio 进程使用 `skills/list` 和 `forceReload: true`，在本项目及用户目录均识别三个新名、用户级路径、enabled=true，错误列表为空，旧名不再出现。查询后临时进程退出；没有启用后台服务。接口语义依据 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。这证明本机同版加载器识别成功；桌面 UI/当前会话刷新、自动触发和其他宿主兼容仍未实测。完整结果见 [验证报告](validation-report.md)。

此前用户级安装和旧项目级 `af-product-intelligence` 别名归入本地备份的记录保留在验证报告历史段落中。此次用户级新名是从现有作者源同步的完整副本，不是恢复旧项目别名，也未提供旧名兼容转发。

## 在其他工作环境使用

如需复制到宿主，先明确授权与宿主支持的位置，再核对当前名称、清单、内容差异、用户修改、目标占用及旧名依赖。保护旧副本后复制完整文件夹，核对内部链接和内容散列，实际验证宿主加载；兼容性未知时保留旧入口并记录待办，不自动删除。

只编辑 `skills/` 作者源；使用副本不是第二份编写源。无需运行 `af`、`python -m agentforge` 或修改版本锁。仓库不提供安装器、自动更新或后台同步，安装器旧状态在忽略备份中只供恢复历史资料，不是当前操作说明。

## 私有材料与反馈

原始任务、未经编辑的回答和私人研究资料放在 `.local/skill-evals/`；公开研究摘要必须脱敏。具体收益、误判和额外负担按 [AF Skill Quality Loop](skill-evaluation.md) 记录，结构、行为、对照、真实价值分别判断。重要改进先保存问题、假设与基线，再做定向对照和回归；无需为每次日常使用做完整评估。未执行项记 `not-run`，没有用户反馈时真实价值未知。
