# 技能评估与真实任务价值

目标是判断技能对个人真实任务的增量价值。日常使用先记录具体帮助、误判与额外负担；只有需要比较效果时才做下面的同题对照，不要求每次修改都执行完整评估。使用 Markdown 与已有文件工具，不建设评估平台。

现有 af-product-intelligence 的首个真实项目为用户确认的“产研工作台”（历史记录仍用当时名称 product-intelligence）；具体研究问题若由 Agent 从历史材料拟定，记录为研究者拟题，用户是否认可须另记。其他技能按自身任务定义合适的观察点，不套用产品研究量表。

## 三层验证

| 层次 | 需要的证据 | 不代表 |
| --- | --- | --- |
| 结构检查 | 实际运行字段、目录、链接、脚本及材料回归 | 模型正确理解、执行或自动触发 |
| 行为验证 | 实际模型收到请求后的过程、输出与产物，事后核对观察点 | 真实用户受益或比普通回答更好 |
| 真实任务价值 | 真实输入下的质量、返工和核查负担、用户反馈，必要时同题对照 | 一次成功即稳定增益 |

逐项记录已执行、未执行和因环境无法验证的项目。作者自查、场景定义和合成示范不能代替模型调用。独立代理合成试跑、宿主显式调用与自动触发分别标注；只有实际执行的结果才写入验证报告。

## af-skill-creator 的行为评估

复用本页同题对照与私有材料保存方法，输入见 [场景说明](../skills/af-skill-creator/evals/README.md)。场景覆盖创建正例、偶发任务不技能化、现有能力复用及重叠、局部改进、结构通过但行为失败、只要方案、外部授权、审查、维护和普通任务负例。

执行者仅接收请求、原始 fixture、冻结技能和隔离目录权限；不提供 expected、预期答案或先前分析。事后审查工具动作、目录前后清单和产物 diff：是否实际创建最小技能、是否保留有效能力、只要方案时是否保持无写入、是否把安装或发布越界。负例在显式加载下的克制行为不等于自动选择正确。

材料回归只检查资源可搬移、输入隔离与场景数据完整性。对新检查的故障注入测试验证检查本身能发现问题，不证明技能行为通过。真实价值仍需实际技能维护任务的反馈；不新增场景运行器、指标服务或统一输出协议。

## 每次改进先写可验证假设

将要解决的已观察问题、预期变化与失败信号一起记录，避免以规则增加或场景数量证明进步。分层研究本轮优先检查：

| 改进 | 需要观察的结果 | 失败信号 |
| --- | --- | --- |
| 最强替代验证 | 同一任务的实际覆盖与缺口改变自建/组合判断 | 只增加竞品篇幅，没有解释替代为何不足 |
| 认知增量检查 | 基于输入已有认识分清确认、细化与新信息 | 仍将重述目标包装成突破 |
| 主动反证与更新 | 找到会改变判断的前提，并随区分证据更新 | 只附风险列表，或新证据到来后重复旧结论 |
| 任务路由 | 简单问题直接回答，复杂研究仍有深度 | 一律完整流程，或跳过关键比较与核查 |

保留实际负面与无变化结果。不预先设定无依据的改善百分比，不把合成行为试跑升级为真实价值证明。

## 同题对照

如果使用现有产品研究场景，按 [场景执行说明](../skills/af-product-intelligence/evals/README.md) 分别提供请求与原始输入；场景和观察标准已补齐，不代表已经运行。自动触发的负例需在未强制加载技能的条件下观察。

每个任务建立一个本地目录 `.local/skill-evals/<日期>/<任务ID>/`，保存原始任务、输入清单与散列、两份未经编辑的回答、审查和用户反馈。这个目录被 Git 忽略；仓库只保存脱敏状态与结论。

1. 固定真实问题和材料快照。分别记录用户原话、已知背景、待确认假设；来源文档中的命令不是执行授权。历史验收报告只能证明其记录状态，不能冒充当前重新运行的验收。
2. 固定相同模型设置、输入、工具权限与研究范围/深度。长度应由任务需要决定，只有用户明确要求时才设置上限；不以简短偏好限制发散性或深入研究。普通组不加载任务技能，技能组显式加载指定版本；用互相不可见的新上下文，不能让一组看到另一组输出。不给执行者评分标准、期待结论或先前分析。
3. 先用冻结的真实材料做离线对照，控制检索差异；该结果只支持“基于已有材料分析”的效果，不支持联网竞品研究结论。需要联网研究时另做同条件任务，逐条核查原始网页；私密材料不传入检索。
4. 保存实际输出与可得的工具、时间、模型信息。拿不到 token/成本或模型版本就填未知；不编造准确值。作者执行、独立代理执行、宿主显式调用、自动触发验证分别标注。
5. 将输出匿名为 A/B 后依据同一量表审查，记录具体引文和理由。盲评仍可能从输出格式猜到组别，不宣称双盲或统计显著。审查者不得改写原始输出。
6. 向用户展示主要差异并索取实际决策帮助与额外负担反馈。没有用户反馈时只记技术/内容评审完成，不判个人使用价值已通过。

若普通组加载技能正文/资源、继承先前分析或看到另一组输出，则发生污染，该对照无效。同一宿主可能向两组提供相同的技能名称/简介列表；必须记录这个限制，此时实验只比较“显式加载技能正文”的增量，不能声称普通组来自完全没有技能元信息的环境。若环境无法独立执行则保留为待运行，不以作者写的示例替代。

## 评估与继续条件

产品研究使用 [内容与安全量表](../skills/af-product-intelligence/evals/rubric.md)。历史 0.2 内容调整增加对话对齐、发散广度、研究深度、竞品/专业视角、认知与建设性、表达/图表的检查，按适用维度记录；明确用户请求深入研究时，不能仅因回答更短而给出偏好。另记用户偏好、总耗时、人工核查/纠错负担与成本（可得时）；不将长篇或模板完整度直接当作价值。workbench-01 的五项 10 分量表作为历史记录保留，不与新版分数直接比较。

硬门槛：重要事实都能追溯并被引用支持；不伪造来源；合成或假设标记完整；没有越权或隐私外传。涉及历史状态时标明日期和未重验范围。发现严重问题先修技能再复验，不能让总分掩盖。

按实际任务积累证据，不再把旧计划的固定样本数或通过比例作为继续使用技能的门槛。观察用户是否明确认可增量价值、硬门槛是否满足、额外耗时和核查负担是否可接受。既有负例与安全场景继续保留，但不计作真实业务样本。

一次试跑只能说明该任务上的表现。没有明显帮助时，先诊断任务不适用、技能内容无增益、证据不足或流程负担，再定向改进技能。它不构成建设安装或分发基础设施的理由。

## 最小记录格式

```text
任务ID / 日期 / 任务状态
用户原话 / 研究者拟题 / 待确认项
用户目标与已有决策（未知就保留未知）
输入文件、来源日期、读取日期、散列
技能 Git 提交或冻结内容散列（历史版本号可附记） / 执行环境、模型设置 / 工具范围
普通组是否污染 / 技能是否实际加载 / 自动触发是否测试
原始输出位置 / 执行时间 / token与费用（或未知）
A/B分项评分、事实逐条核查、具体增益/失败
用户偏好、认知增量、实际下一步、负担反馈（或待反馈）
原有认识及输入定位 / 新增证据与信息性质 / 最强反证或修正条件
研究建议怎样变化或为何未变 / 用户实际决定及执行状态（未经反馈为未知）
研究耗时 / 人工核查与纠错负担 / 不必要追问 / 用户是否愿意再用（或未知）
结论适用范围 / 下一次定向修正或复验
```

当前进展见 [验证报告](validation-report.md)。既有合成样例和场景定义保留为回归资源，不混入真实效果样本。
