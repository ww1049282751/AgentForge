# ADR 0007：统一 af- 命名并增加技能建设能力

日期：2026-10-25。状态：已采纳。依据：本次用户实施交接要求；延续 [个人技能集合](0004-personal-skill-collection.md)。

## 决定

所有新技能必须使用 `af-` 前缀。目录名与 frontmatter 的 name 完全一致，使用小写字母、数字和短横线且唯一。迁移现有作者源，不改写产品研究核心方法。

| 原作者源 | 当前作者源 | 职责 |
| --- | --- | --- |
| `skills/product-intelligence/` | [af-product-intelligence](../../skills/af-product-intelligence/SKILL.md) | 产品方向、需求机会、替代方案与选择 |
| `skills/product-deep-dive/` | [af-product-deep-dive](../../skills/af-product-deep-dive/SKILL.md) | 具体产品、机制、源码与架构研究 |
| 无 | [af-skill-creator](../../skills/af-skill-creator/SKILL.md) | 技能必要性判断、设计、创建、改进、审查、评估与维护 |

af-skill-creator 用轻量 Skill Spec 支持创建决策，五种工作模式按任务选择，不要求全阶段或完整目录树。只要方案时不落盘；普通业务或产品研究不转为技能工程。三个技能均独立使用，不建立跨技能调度、运行时、注册表、安装器或分发体系。

结构检查、实际行为与真实价值分别取证；沿用已有轻量检查和评估记录，不把场景定义或单元测试数量当成有效性证明。完整实施与未覆盖项见 [验证报告](../validation-report.md)。

## 历史与授权边界

历史决定、研究和安装记录保留当时名称、版本、路径叙述与结果；其中指向当前文件的有效链接更新目标，并由本决定说明映射，不重写旧证据。此前项目级旧别名的备份记录不等于本次提供兼容别名。

仓库仍为唯一编写源。迁移前保护工作区并校验备份；本次仅只读检查已有宿主副本，后续同步需明确授权，并先核对目标占用、内容差异、用户修改和宿主命名依赖。没有实际加载验证不得宣称兼容；不能随源目录重命名自动删除旧入口。

以前的远端同步授权不自动延伸到本次。未授权不推送、不建 Release/tag、不改宿主或其他项目配置、不安装副本、不创建后台任务。

后续授权与执行：2026-10-25 用户明确要求先备份保护修改，再迁移两个旧宿主名称、安装 af-skill-creator，核对内容和加载后提交推送。已保护旧副本及仓库文件、核对 54 个安装文件与作者源一致，并使用桌面同版加载器实际识别三个启用的新名。远端结果见验证报告；本段不改写前阶段的授权状态，不包含 Release/tag、后台更新或其他项目配置。
