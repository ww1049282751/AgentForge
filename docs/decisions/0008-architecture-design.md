# ADR 0008：独立架构设计技能

日期：2026-10-25。状态：已采纳（作者源实施，不表示真实价值已验证）。

## 必要性与替代

用户交接明确要求填补从产品理解到正向架构决策的缺口。现有 af-product-intelligence 面向需求、机会与产品选择，af-product-deep-dive 还原已有机制与实现，af-skill-creator 负责技能建设。架构约束、事务边界、兼容迁移和验证任务可独立输入、输出及评价；混入研究技能会模糊“还原现状”和“提出设计”的证据边界。

一次性提示或参考文档适合单个设计问题，但难以稳定覆盖六种重复任务及权限/证据约束。这里按明确建设需求创建最小完整技能；预期重复价值来自任务类型，不伪造真实使用频率或收益。保持既有技能正文、资源、场景与量表原样，不强制跨技能调用。

## 轻量 Skill Spec

| 维度 | 本次选择 |
| --- | --- |
| Goal | 将需求和约束转为可实施、可验证、可修正的架构决策 |
| Scope | 正向设计、架构评审、技术选型、关键流程、演进与验证；不接管方向研究、机制逆向、一般编码及运维 |
| Trigger | 六种模式按实际请求选择；简单问题直接答，附仓库地址不扩成全面审计 |
| Inputs | 需求、现有材料/实现、团队/部署/技术约束；缺失条件显式标记 |
| Outputs | 条件式推荐、边界/接口/数据/异常机制、ADR 和验证/迁移任务，按需交付 |
| Workflow | 约束 → 最小模型 → 关键决策与简单替代 → 机制细化 → 验证 → 收束；证据可使流程回退 |
| Resources | 四份按需方法、两个可裁剪模板、一份合成示例、独立 fixtures/场景/量表 |
| Constraints | 宿主独立、内部资源可搬移，不虚构指标与验证，不自动执行外部变更 |
| Evaluation | 六类核心场景加未知、范围、负例、权限和验证诚实；四类证据沿用 AF Skill Quality Loop |
| Maintenance | 真实使用反馈、可靠性失败、选型事实变化、迁移遗漏或资料失效时定向修正；保留失败与回归 |

## 取舍与授权

入口维护路由、关键判断和停止条件，具体机制放 references，模板不强制。没有新增运行时、安装器、平台、版本锁或通用架构格式。架构专业观察留在技能 evals；现有通用检查器不增加领域规则。

基线为干净工作区的 `e67ed579dd952b709740bb5ad5be7ec38773ee81` 与本地逐文件快照；新技能没有旧行为输出，不能宣称前后 improved。用户随后明确允许独立子代理试跑和评审，执行者使用新上下文且不读预期。实际证据与限制见 [验证报告](../validation-report.md)。上述初始实施阶段没有安装、覆盖副本、改宿主、提交推送、Release/tag 或后台任务授权。
