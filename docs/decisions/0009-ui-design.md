# ADR 0009：独立的 UI 设计、改进与评审技能

日期：2026-10-25。状态：采用；作者源实施，实际验证范围见 [本轮报告](../evidence/ui-design-20261025-summary.md)。

## 必要性与替代

用户明确要求依据 UI 技能交接文档建设作者源。当前四个技能分别负责方向、机制研究、架构和技能建设；把任务转成界面层级、视觉、交互与实际观察是独立交付边界。反复稳定增益仍是待验证假设，不把创建意愿当效果证据。

最强简单替代是一次性明确提示，配合现有 UI 工具与项目规则。现有外部 frontend-design 强调视觉意图，ui-ux-pro-max 提供设计检索，web-design-guidelines 提供 Web 审查；这些能力可用但不成为本技能依赖。新技能固化跨宿主的任务路由、设计继承、异步语义、证据与授权判断，不复制外部风格黑名单或检索数据库。若对照长期无增益，应缩减或停止扩展，而非建设平台。

## 轻量 Skill Spec

| 项 | 本次决定 |
| --- | --- |
| Goal | 从真实任务与约束得到可理解、可实现、可检查的 UI 决策 |
| Scope | 信息架构、视觉、交互、项目继承、响应式、无障碍、按请求原型/实现/评审 |
| Trigger | design / improve / review；纯方向、后端和无需 UI 判断的修复不触发流程 |
| Inputs | 任务、内容、设备、截图/代码、设计资产、接口事实和交付权限；未知不编造 |
| Outputs | 按深度给决策、局部建议、发现、状态、原型/代码及实际证据；小问题直接答 |
| Workflow | 读上下文、沿任务决策、必要时对标、按权限制作、观察修正、收束；非强制流水线 |
| Resources | 入口；设计推理、视觉交互、项目继承与实施评审三份参考；可裁剪模板；场景和量表 |
| Constraints | 宿主/框架独立、内部链接可搬移、保护修改、权限与证据诚实 |
| Evaluation | 统一质量闭环四层；合成正例/负例/边界/权限、截图及条件运行，实际结果另记 |
| Maintenance | 用用户反馈、真实失败、来源变化和回归驱动局部改进；保留失败快照与重评条件 |

## 结构与范围取舍

将项目上下文继承并入实施评审参考，避免第四份重复文档；不建立额外示例目录，必要合成输入集中在 evals/fixtures。只有 screenshot 场景提供图片，源码题不当截图题。量表评方案与实际渲染时明确不同证据范围，硬失败不能用总分抵消。

复用现有场景 schema、标准库检查器和材料测试函数；仅新增两项可移植性/输入隔离测试，不给通用检查器增加 UI 字段，不建立统一执行器。实际模型调用和一次性运行记录留在忽略目录。

不建设产研工作台产品、多 Agent 系统、中心设计资产、安装器、插件包装或后台更新。其他四个技能的协议不变。本次只在仓库编写和验证，不安装使用副本、改变宿主配置、提交、推送、部署或创建 Release/tag。此前授权记录保持原范围。
