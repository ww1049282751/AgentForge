# 当前路线：个人使用与技能效果优先

更新：2026-10-24。依据：用户明确要求个人使用优先、冻结自建运行时扩展、先验证真实任务效果、再做最小原生插件验证、暂不推送。此计划替代最初按安装/更新运行时推进的里程碑顺序；已完成工程事实保留在验证报告和 Git 历史中。

| 阶段 | 当前状态 | 产出与退出条件 |
| --- | --- | --- |
| P0 路线收敛 | 已确定 | 个人技能库定位；运行时冻结；明确不推送 |
| P1 真实任务试跑 | 首个材料型对照与内容审查完成；待用户反馈 | 用户选择“产研工作台”为首个真实项目；两组核心建议相近，尚不能判定技能净增益，见试跑摘要 |
| P2 小批量复验 | 尚未开始 | 积累 5 个真实任务，必要时扩至 10 个；观察反复出现的收益与失败，定向改技能，不追求凑数量 |
| P3 最小原生插件验证 | 等待 P1/P2 形成可审查结论 | 只验证一个技能的原生发现、显式调用、版本来源与清理；列出有证据的原生缺口 |
| P4 基础设施取舍 | 后续决策 | 只为已证实且实际需要的缺口决定是否恢复部分运行时开发；不自动恢复扩展 |

P1 首题由用户给出产品名；研究问题可从既有项目材料拟定，必须标注哪些是用户原话、哪些是研究者拟题/假设，不能伪装成用户已确认的路线。已有合成产研工作台样例不计入真实样本。

用户随后明确 Product Intelligence 的定位是发散性调研、深入分析、竞品分析、专家评审与认知补齐，并要求方向不清时多轮追问、产出更丰富且有建设性/突破性。已按 [ADR 0003](decisions/0003-product-research-positioning.md) 修订为 skill/plugin 0.2.0。此前最小行动窄题不能代表这一完整定位；当前先做定向行为复验，再回到用户真实研究任务。受控脚本测试不冒充新增真实用户样本。

冻结范围：新的 CLI 命令、源类型、宿主适配器、市场/发布系统、自动更新、通用依赖求解器及通用评估平台。不因已有代码形成沉没成本而继续扩展。影响当前已授权试跑或数据保护的实际缺陷可做最小维护，先记录具体证据。

当前运行时、测试、schema、安全检查、已有技能安装和备份均保留。真实材料与完整输出进入 `.local/skill-evals/`，不提交。仅把脱敏结论、方法和已确认决定写入 docs。禁止把其他项目文件作为本仓库公开样例复制提交。

本轮不推送、不创建 Release/tag、不改全局技能或 marketplace 配置。原生验证的具体命令在进入 P3 时按本机版本和官方文档核对；当前不预先执行。
