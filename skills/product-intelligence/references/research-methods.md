# 产品研究方法

按当前困惑选用方法，可以组合或返回前一步；不是每次完整执行的流水线。质量来自新解释、有依据的比较与能推动判断的建议，不由章节数量、资料条数或篇幅决定。需要示范时查阅 [分析正反例](analysis-examples.md)。

## 问题重构与竞争性解释

先将问题表述拆成用户观察到的现象、期望进展、提出的方案与隐含前提。检查现象是否有材料依据，以及“解决了现象”是否真的改善目标；例如低频任务不一定需要提高使用频次。

当不同解释会改变产品选择时，展开最有价值的分歧，不凑固定数量：

| 解释 | 现有支持/冲突证据 | 若成立，应观察到什么 | 什么证据能区分解释 | 会导向什么选择 |
| --- | --- | --- | --- | --- |

优先查找能区分解释的材料，而不是不断收集支持最初设想的案例。解释可以并存；区分不同人群、情境或因果环节。没有证据判断时保留分歧，已有充分证据时也不为反对而反对。研究发现需要重新界定问题时，说明变化及其影响。

## 需求挖掘：从事件到期望进展

沿“具体事件 → 触发情境 → 当前做法 → 阻碍/代价 → 希望取得的进展 → 需求假设”梳理。优先使用近期实例、实际工作流或原始反馈；没有这些材料时，说明哪些只能形成待验证解释，不编造访谈。

- 功能请求先追问用途与下游任务。例如导出可能服务于交接、审计、二次分析或迁移；不要直接认定用户需要更强的导出功能。
- 记录现有替代、维持现状的理由、放弃或切换的触发点。使用者、决策者与承担成本的人不同时，分析各自的收益、责任和阻力。
- 记录证据支持到的人群/情境；少量个案、公开投诉和厂商案例不能推出需求比例。需求存在、值得优先解决、用户愿意切换、某方案有效，是不同判断。

有材料支持的需求与探索性机会假设可以并存，但不可混写。对前者链接原始事件及适用范围；对后者写明推演依据、成立条件和证伪方式。没有访谈等输入时可画假设地图，不能将其称为已验证的用户机会树。

## 发散性调研

把用户最初方案视为待探索的切入点。沿用户任务、被忽略的人群、不同使用时机、价值交付方式、相邻领域机制等方向扩大选择空间。区分“同一机制增加功能”与“改变解决问题的方式”。

按问题选择能带来实质差异的角度，不要求逐项产出：

| 角度 | 用于展开方向的追问 |
| --- | --- |
| 任务与人群 | 用户要完成工作，还是避免这项工作？谁被当前定义忽略？ |
| 介入时机 | 能否在问题发生前预防，或在下游环节直接交付价值？ |
| 控制权 | 人与系统各自最适合承担什么，哪些判断需要可解释和可撤回？ |
| 价值交付 | 需要报告、工具、服务、决策支持还是持续更新？ |
| 相邻机制 | 其他领域如何处理类似的信任、协作或不确定性？迁移需要什么条件？ |
| 默认前提 | 取消主动输入、全自动、独立应用等假定后，会出现什么路径？ |

去掉功能名称后仍能解释不同的用户价值与作用机制，才算有实质差异的方向；同一方案的包装或功能增补可以保留为变体，但不冒充不同战略。

有意义的方向应能说清：面向何种任务，改变哪条机制，相比现有替代新增什么价值，依赖什么条件，为什么值得进一步研究。可以提出跨领域类比、反直觉假设或高不确定性的愿景，但明确哪些是构想，不把新奇当有效。不要为凑数量列出互相改名的方案，也不要以缺少现成证据为由删去所有大胆假设。

分别判断新颖性与证据强度，为保留的方向写明最大未知和最强反对理由。可以给有条件的推荐，解释为何优先、哪些其他方向仍值得保留；用户在开放探索时，不强制收束为唯一方案或立即开发。

## 深入分析与认知补齐

从可观察的行为或设计出发，解释背后的动机、激励、信息结构和约束。检查同一现象的竞争性解释，以及结论在何种边界会反转。把技术能力、产品价值、用户行为和商业成立条件拆开，不用其中一个替代另一个。

对会影响选择的结论，连接“观察与证据 → 竞争性解释 → 机制与成立条件 → 反例/区分证据 → 改变的产品判断”。解释具体改变了什么：激励、信息分配、等待与协作成本、控制权、信任、迁移阻力或商业约束。检查相关现象是否可能由其他变量造成；叙述连贯不等于证明因果。

用两个问题校准深度：

- 换成其他产品名，这条建议是否仍原样成立？若是，具体到谁、哪个环节、为什么受阻、改变后有什么取舍；缺失材料则标明未知。
- 什么证据或条件会使结论反转？说明最强替代解释与可区分它们的观察，而不是附上泛泛的风险清单。

对认知缺口说明：原先可能把什么当成理所当然；证据支持的新理解是什么；它改变哪项选择；还需要什么材料区分不同解释。针对缺口补概念、机制和反例，不堆砌术语或一般知识课。

可写成“先前理解/本次暂用假设 → 新证据或解释 → 改变的选择 → 修正条件”。用户没有表达过的观点不能归到用户头上。没有新发现时说明哪些判断得到支持、哪些仍未知，不强行制造惊喜。

先对照输入中已有的明确认识，再判断增量。例如，用户已要求区分执行完成与成果验收时，再讲这一区分属于确认或展开，不是新发现。真正的增量可以是外部证据新增的约束、一个反例、适用边界或会改变取舍的机制。结尾应指出它比原有认识多了什么；不要借一个更弱的研究者假设制造认知跃迁，也不为追求新颖而否定已经充分成立的判断。

## 竞品与范式对照

先说明选样依据，再读原始资料。对比当前用户用来完成同一任务的直接产品、不同类别的相邻方案、人工替代或维持现状，按需选择能体现机制差异的对象。对齐人群、触发场景与目标后，再比较具体工作流；资料不齐或成熟度不同不做简单功能数量排名。

当问题包含“是否值得另做产品”时，找一个最可能已经满足核心任务的现有方案或工具组合，用同一具体任务追踪它如何开始、形成结果、复用或更新结果。区分文档已说明的覆盖、可配置或组合实现的部分、需要实际使用才能判断的断点，再讨论独立产品机会。不能只从多款相邻产品各借一个机制，就推定它们之间存在值得自建的空白；也不要求穷举竞品或把所有大胆方向收缩成现成工具组合。

| 分析维度 | 需要回答的问题 |
| --- | --- |
| 用户任务与触发场景 | 用户为何开始使用，原先如何完成任务？ |
| 核心工作流与控制权 | 人与系统分别做什么，信息如何流动，在哪里做决定？ |
| 价值机制与体验 | 哪个设计带来什么潜在收益，证据是厂商自述还是可核查效果？ |
| 约束与商业条件 | 迁移成本、数据权限、协作成本、收费机制等如何影响选择？ |
| 借鉴与机会 | 哪条机制值得迁移，哪些条件不成立，哪个重要问题仍未解决？ |

顺着“用户何时进入 → 输入什么 → 人与系统分别做什么 → 如何获得价值 → 下游如何使用”重建工作流。用下列机制迁移卡展开重要启发，也可用文字表达：

| 字段 | 分析要求 |
| --- | --- |
| 具体做法与证据 | 谁在何时如何使用；来源支持到哪一步 |
| 作用机制 | 改变了什么行为、信息、成本或激励；收益是观察还是推断 |
| 成立条件 | 依赖的人群、使用频率、数据、渠道、信任、协作或商业条件 |
| 代价与反例 | 牺牲什么，何时无效，哪些替代解释尚未排除 |
| 迁移方式 | 在当前问题中借鉴哪部分、如何调整、哪些条件不成立 |
| 区分证据 | 什么观察会支持借鉴或让我们放弃这条路径 |

发现功能空白时检查：竞品可能忽略了需求，也可能需求较弱、成本过高、与商业激励冲突，或用户不愿承担切换成本。公共资料未提及只能算“未找到”，不能直接断言不存在。机会判断需连接具体需求与可行的价值机制。

无法访问真实产品时明确“依据公开文档”或“依据提供材料”。缺少资料时保留未知，不用记忆补造当前功能/价格。联网不可用时可以建立研究框架和待核查对象，但不能写成竞品调查已完成。

## 专家视角与评审

真实观点优先作者原文、研究、完整访谈或演讲，注明作者、语境、日期和适用前提。引用某个理论解释方案是研究者的应用，不等于该理论作者亲自评审或支持方案。

当需要多角度挑战而没有真实专家参与时，明确写“Agent 模拟专业视角”，按问题选取专业立场，例如用户研究、产品战略、交互、人机协作、技术可行性或商业模式。不要冒用真人姓名。每个视角都要提出具体判断、关键质疑、可接受条件和可建设性修改，避免几位虚构专家轮流赞同。

最后归纳分歧：不同立场在优化什么、哪些前提冲突、什么证据会改变判断、哪些改动可兼顾目标。不以角色数量或虚构投票分数制造权威，不虚构外部联系或访谈结果。

## 建设性与突破性

把研究收获转成方向或设计原则：针对痛点提出机制、组合已有能力形成不同体验、指出可以舍弃的默认约束、给出有条件的选择。明确近期可尝试的路径与远期更大胆的图景如何关联，而不是一律削减为最小功能。

为突破性方向附上反对论证：最大的成立条件、可能失败的原因、何种证据支持继续投入。验证计划不必都变成即时开发实验；也可以是产品使用、用户观察、机制原型或专家材料核查。用户没有提供基线时不随手规定精确成功率。

当关键命题和方向差异已经解释到足以支持本次目的时交付。剩余未知依赖不可得资料、访谈或真实使用时，说明受限结论、所需证据与下一步，不用更多相似网页替代缺失证据。新材料改变问题解释时返回相关步骤，避免把研究当不可回退的流水线。
