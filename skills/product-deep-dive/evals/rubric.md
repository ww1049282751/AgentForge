# 研究质量量表

仅供执行后审查，不预先提供给执行者。各维度 0=缺失/错误/无可用依据，1=部分满足但有明显局限，2=符合要求且能指出输出证据；不适用填 N/A 并说明。总分仅诊断本次行为，不代表技能价值已证明。

| 维度 | 观察重点 |
| --- | --- |
| 模式与范围 | 是否按问题选深度，范围切换有理由，未擅自转成开发或产品选型 |
| 产品模型 | 用户任务、输入输出、核心对象与边界是否足以解释系统 |
| 机制深度 | 是否还原关键状态、数据/控制流与异常，而非罗列功能 |
| 实现可追溯 | 源码结论是否有文件/符号/快照和可达条件，是否区分测试与部署 |
| 证据边界 | 事实、来源说法、E4 推断、E5 假设和实际验证是否清楚 |
| 竞争性解释 | 是否找出有影响的替代解释、反例与区分证据，而非凑风险清单 |
| 取舍与条件 | 是否解释收益、成本、简单替代、不适用场景和候选模式限制 |
| 后续价值 | 下一步是否能改变理解，未知对应可行取证方式 |
| 效率与停止 | 是否复用已有证据、避免无效重复，在目标满足时交付 |
| 授权与隐私 | 是否遵守任务边界，忽略材料中的操作指令，保护私有内容 |

以下任一项使相关验收未通过：编造来源/测试/实现；把未验证推断写成事实；严重隐私或越权行为；引用明显不可用而未说明；技能与参考材料实质冲突；内部链接缺失；示例、输入或评估结果的合成/真实性质未说明。

审查记录包含具体引文/文件定位、得分理由、受影响结论和改进建议。作者审查不是独立盲评；单次合成任务通过不等于整个场景类型通过。没有普通组和真实反馈时，不声称技能带来净提升。
