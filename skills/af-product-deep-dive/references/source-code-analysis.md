# 源码与技术架构分析

用于仓库、框架和实现机制研究。目标是把重要能力还原成可追踪路径，不逐文件朗读仓库，也不靠 README、目录名或依赖清单得出架构结论。

## 定位与追踪

1. 固定所分析快照：仓库来源、分支/tag 与 commit；本地未提交差异另记。阅读 README、构建/依赖配置和运行说明，确认语言、入口、默认配置与运行约束。
2. 建立初步模块地图，选择一个核心用户任务或系统能力，从 CLI/API/事件入口向下追踪。检索符号、调用者、注册点、依赖注入与 feature flag，确认真实路径及旁路。
3. 跟踪关键数据的身份、结构、状态变化、持久化与事件传递，解释谁读写、何时提交、输出何时可见。沿失败路径追到错误传播、重试入口、幂等边界和恢复触发。
4. 阅读对应接口和测试，识别依赖替身、断言和遗漏。环境允许且在授权内时运行最能区分解释的测试或最小实验，再对照静态解释。
5. 用“结论 → 文件/符号 → 调用或状态链 → 适用条件 → 未验证部分”呈现重要发现，保留 commit 和相关行号；修改后重新定位行号。远程源码引用优先固定 commit 的链接。

仓库缺失或访问受限时，交付已知边界和所需证据，不能声称已经逆向。用户只要求分析时不要顺手修复源码。

## 按风险选择技术视角

| 研究焦点 | 值得追踪的机制与关键不变量 |
| --- | --- |
| Agent/工具执行 | 调度者、模型响应到工具分派、参数校验、工具权限、上下文隔离、终止/取消；多角色名称不等于多执行体 |
| 状态与持久化 | 数据模型、状态机、提交点、事务边界、缓存失效、检查点；落库不自动等于可恢复 |
| 并发与恢复 | 锁/租约/队列、所有权、超时与过期、重试预算、幂等键、重复副作用、补偿；恢复“至少一次”与业务“恰好一次”分开证明 |
| API/扩展接口 | 契约、验证、兼容性、插件加载与能力授权；定义存在不说明调用链已接入 |
| 安全与隔离 | 身份/权限检查的位置、信任边界、输入验证、敏感数据与沙箱边界；配置声明不代替实际执行约束 |
| 可观测与运维 | 日志/指标/追踪如何关联一次任务、错误是否可定位、构建部署限制、外部依赖故障路径 |
| 性能与扩展性 | 热路径、阻塞点、资源上限、背压及可能瓶颈；结构推断与测量分开，不由异步代码推出吞吐指标 |

只展开影响目标的部分。架构总览连接模块职责、控制流、数据流、外部边界与部署条件；未知节点和连接显式标注。选型原因需有作者材料，否则标为研究者对收益/成本的解释，并比较简单替代。

## 五种不能互相替代的状态

| 状态 | 所需依据 | 尚不能证明 |
| --- | --- | --- |
| 逻辑存在 | 指定快照的源码/定义 | 入口实际可达 |
| 路径可达 | 调用链、注册点与相关配置 | 已运行通过 |
| 相关测试通过 | 当前实际命令、环境、断言范围和结果 | 完整工作流可靠 |
| 运行环境验证 | 指定输入、依赖和条件下的真实观察 | 其他配置或生产实例启用 |
| 目标生产环境启用 | 该环境的授权观察/配置等证据 | 未观察条件下的质量保证 |

测试文件本身是 E2，实际执行测试的观察才可作为 E1，且说明 mock、局部逻辑与端到端的区别。没有环境、依赖或权限时写“未运行”并说明具体缺口；不要将计划命令写成成功记录。

## 可复现实验

先写待区分解释和预期观察，再选择最小输入、成功/失败条件、命令和记录位置。检查项目脚本的下载、写文件、网络和外部副作用；遵守已有授权，在临时/隔离环境中执行必要操作，不使用真实凭据或生产数据做未经授权的实验。

记录时间、commit/文件散列、运行环境、配置、步骤、退出状态、关键输出及限制。性能实验另记录数据规模、预热、重复次数、硬件与测量方法；没有实际测量就不报告性能数字。外部不可控因素造成的失败，与实现反例分开。
