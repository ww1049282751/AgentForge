# 候选设计模式

仅为有价值的机制创建记录，不把单个案例提升为普遍规律。状态可写“候选”或“已在所列范围核查”，并注明未验证部分。

| 字段 | 记录内容 |
| --- | --- |
| 名称与问题 | 具体约束、触发场景和希望保持的不变量 |
| 来源与证据 | 产品、版本/commit、研究日期、具体主张与原始证据；哪些只是来源说法或推断 |
| 核心机制 | 状态、数据、控制权怎样改变；必要条件 |
| 对比与取舍 | 与相关替代的区别、收益、复杂度和成本；替代是否实际调研 |
| 适用与不适用 | 环境、规模、依赖、组织或用户条件 |
| 失败与反例 | 机制如何失效、哪些解释仍不能排除 |
| 迁移（需要时） | 借鉴什么、必须改造什么、如何检验前提 |
| 待验证与修订 | 区分证据、下一步、已有相似条目、旧判断和更新原因 |

归档仅写入授权位置，先检查既有记录；研究模式抽象不等于已经批准产品实现。
