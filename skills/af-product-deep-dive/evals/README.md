# af-product-deep-dive 行为评估

[场景定义](scenarios.json) 至少覆盖源码 Agent、仅页面 SaaS、基础设施、双产品机制比较与证据不足，并有方向选择/普通修复负例。所有 fixtures 都是明确标注的合成输入，正例可离线运行；存在文件或通过静态检查不表示模型行为通过。

在 AgentForge 仓库维护时，以仓库根目录的 `docs/skill-evaluation.md`（AF Skill Quality Loop）为统一协议，分别记录结构、行为、对照和真实任务价值，采用其结果状态与改进记录。重要改进先冻结问题、假设、基线输出及技能快照，再按本技能量表检查目标能力和原有能力。未执行记 `not-run`，受环境或权限限制记 `blocked` 并说明；源码证据、机制和架构判断仍按本技能观察标准审查。这里是仓库维护引用，不是技能运行依赖；独立复制本技能后沿用目标项目规范及本页执行方法。

## 执行与审查

1. 选取相关场景，将 request、inputFiles 对应的原始材料与技能入口交给执行者。不要交付整份 scenarios.json、expected、评分标准、示范答案或前次结论。执行者只按当前任务读取相关技能资源；若意外看到评分或示范材料，记录污染。
2. 用新上下文执行；若要同题对照，两组互不可见、输入和工具范围相同，普通组不读技能正文。负例不要强制加载技能，必须有宿主选择记录才能判断自动触发，不能从回答样式反推。
3. 源码样本仅用 Python 标准库和临时目录，无真实模型/API/凭据。原始输入不改写；可将代码复制到隔离目录执行已有测试，补充实验也留在该目录。实际命令、退出状态、输出与文件定位须保留。
4. 保存未经编辑的回答后，再读取 expected 和 [量表](rubric.md) 逐项审查，给出原文依据与局限；硬性失败不能用总分抵消。修正技能后保存新快照再复验，旧输出不覆盖。
5. 作者仓库内原始任务、输入与技能快照/散列、工具记录、原始输出和审查放在 `.local/skill-evals/`；可提交的只有脱敏结论。其他环境只写授权位置。示例输出、作者自查、独立模型执行、宿主显式调用及自动触发分别记录。

记录模型/推理设置（不可得填未知）、日期、来源性质、实际读取资源、运行环境、验证范围、失败与未覆盖部分。合成离线试跑不是公开产品实测、真实用户收益、完整能力验证或因果效果对照。真实任务与用户反馈需另行积累。
