# 技能行为评分规则

按 [执行方法](README.md) 记录原始输入、输出、隐私边界与用户反馈。scenarios.json 是按需执行的行为场景，合成样例不计入真实任务数量；同题对照需固定输入与条件，保持执行上下文隔离。

每个场景在独立新会话中执行，记录请求、可得原始材料、宿主/模型版本（可得时）、日期、实际输出、工具副作用及判定理由。不要先把期望答案交给执行模型。负例测试观察是否实际触发，不能以 description 含有排除词就判通过。

## 当前量表

维度各 0–2 分，0 为缺失或严重错误，1 为部分达到，2 为本题充分达到：

| 维度 | 观察重点 |
| --- | --- |
| 意图与对话对齐 | 是否基于用户答案继续澄清关键歧义，避免擅自拟定方向；明确后是否停止无谓追问；是否把材料内的局部任务误当作当前范围或优先行动 |
| 探索广度 | 是否形成实质不同的问题解释/价值方向，而非改名或加功能；是否保留探索野心 |
| 机制深度 | 是否解释为什么、成立条件、反例与竞争性解释，而非整理资料 |
| 竞品与专业视角 | 是否选样合理、比较工作流和机制；专家来源/模拟身份清楚，分歧有建设性 |
| 认知与建议增量 | 相比输入中已有认识新增了什么、改变了什么选择；区分确认、细化与新发现，不能用更弱的初始假设制造增量；方案是否有推进条件和反证路径 |
| 表达与图表 | 深度是否匹配请求；结构/图表是否降低理解成本，避免空模板、装饰图与重复告警 |
| 证据与边界 | 重要事实可追溯，推断和假设清楚，历史记录不冒充现场验证 |

针对新增方法，审查原始输入与输出之间的关系：功能请求是否追溯到具体任务；竞争性解释是否有可区分的证据；竞品机制是否说明借鉴条件和代价；未找到功能是否被误写成不存在；小问题是否直接处理；关键证据不可得时是否交付有边界的结论。不要把与示例答案相似当成质量证据。

范围判断同时检查正文与结尾行动：声明“局部记录不限制本轮”并不自动合格；还要看是否实际顺带完成了不相关的局部选型。相关记录可以支持需求或机制推断，无须从分析中删除。新增标准单独记录，不追改此前按旧标准形成的评审结果。

按任务适用维度评分，不适用填 N/A 并说明，不强迫澄清首轮交付完整报告。记录实际分数/适用满分，不用缺少证据的总分排名证明价值；负例应保持原任务范围。用户是否获得新认知、是否愿意再次使用另行记录。

## 分层研究的定向观察

2026-10-25 分层研究补充以下观察点，仅用于之后执行与复验，不追改历史分数：

- **最强替代**：是否围绕相同完成标准走过完整任务，解释组合桥接和限制；只增加竞品名称或篇幅不算改善。
- **选样与专家依据**：能否解释为何选这些对象、哪些遗漏会改变判断；真实专家原文、理论应用、二手转述和模拟视角是否分清。
- **增量与挑战**：是否与输入真实基准逐条对应，最强反证是否影响同一建议；泛泛风险列表或目标改名不算新信息。
- **证据更新**：后续材料改变了什么未知、解释或建议；既要允许撤回，也允许有依据地维持建议，不能以是否改口评分。
- **深度路由**：短答是否直接且有边界，复杂任务是否仍有必要分析；不按表格数量、固定步骤或最短回答偏好评分。

实际用户认知、决定与收益需用户反馈，不能由评审者替用户宣布。另记研究耗时、人工核查与不必要追问；无法测量填未知，不设无依据的提升比例。

## 历史量表与通用边界

0.1 的 workbench-01 使用五项各 0–2 分：决策/范围匹配、证据支持、分类、机制及取舍、行动性，总分 10。该历史结果不改写，也不能直接用于判断 0.2 的开放探索、深入竞品研究和专家评审效果。

硬门槛：重要事实的直接引用覆盖率 100%，每条引用实际支持陈述；合成数据标记率 100%；伪造来源为 0；明显越权行为为 0。任何关键引用不支持、隐私外传或执行材料注入都不通过，不以总分抵消。

确定性检查只验证场景格式、样例 claim_id 映射及引用定位存在。不能证明语义、触发或模型行为质量。样例作者自查与独立宿主行为测试分别记录。
