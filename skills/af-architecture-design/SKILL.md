# 软件架构设计

把需求和约束转为能指导实施、可以检验、允许修正的设计。独立使用，不要求其他技能存在、固定技术栈或特定工具。重要决策回答：为什么需要、为什么选择、代价是什么、如何验证、何时重评；这些是判断原则，不是每次必填的表格。

## 按任务选择工作

先读用户已有材料、项目规则和相关实现，识别用户要求的范围及交付方式。只在会改变结论的关键歧义处澄清；其他未知注明影响，按条件推进。用户指定模式优先，混合任务组合必要步骤，不重复交付整套报告。

| 模式 | 适用任务与交付重点 | 何时读取资源 |
| --- | --- | --- |
| design | 新系统：候选、推荐、模块与关键交互、实施次序和验收条件 | 有重要取舍读 [决策方法](references/architecture-decision-method.md)；细化方案读 [系统分解](references/system-decomposition.md) |
| review | 现有方案：有定位的问题、影响、证据强度、优先级、修正与复验 | 读 [架构验证](references/architecture-validation.md)，按问题补相关方法 |
| selection | 技术或架构候选：同一约束下比较机制、成本、风险与改选条件 | 读决策方法；涉及质量目标时读 [质量属性](references/quality-attributes.md) |
| deep-design | 核心模块或流程：接口、数据所有权、状态机、事务及异常恢复 | 读系统分解；涉及并发或故障时读质量属性 |
| evolution | 现状到目标：依赖、兼容、数据迁移、分阶段切换、观测和回滚边界 | 读架构验证；模块重划时补系统分解 |
| validation | 验证假设或约束：任务、条件、方法、判据与实际结果 | 读架构验证；选择相关质量场景 |

简单概念或局部比较直接回答，不强制完整流程、ADR 或文件。普通代码修复不扩成架构项目；提供仓库链接也不代表要求全面审计。产品方向探索、成熟产品机制还原、技能建设属于相邻任务：必要时说明边界，复用有来源和限制的成果，不自动加载或调用其他技能。

## 形成可实施决策

1. **确定约束。** 识别目标、用户与关键场景、系统边界、外部依赖、团队与部署、已有技术、数据与一致性需求。分清硬约束、偏好、材料事实、推断、设计假设和未知；不补造规模、SLO 或基础设施。已确认的决定只在新证据影响适用性时重开。
2. **建立最小系统模型。** 沿一个关键任务连接参与者、输入、处理、状态和输出。优先找会改变选择的质量目标与失效路径。既有项目先查实际组件、契约和依赖，不为套用范式改栈。
3. **比较真实候选。** 至少检验最有竞争力的简单替代，按同一约束说明收益、代价、运维与迁移成本。不要把微服务、DDD 或事件驱动当作默认答案；已有决定无需凑替代数量。证据不足给条件式推荐和取证方法。
4. **细化关键路径。** 明确模块职责、允许依赖、接口与错误语义、数据所有权、事务边界、状态转换。根据任务分析重复请求、超时、重试、并发、部分失败和恢复；技术名称不能代替机制。只细化会影响下一步实现或判断的部分。
5. **把质量目标接到验证。** 每个重要要求关联场景、目标或待确认阈值、机制、检查/原型/测试和失败后果。未执行只交付计划；新证据推翻前提时回到相关决策，不继续装饰错误方案。
6. **交付并收束。** 推荐与理由先行，保留重要未决事项、实施顺序、验证条件和重评信号。关键决策有可追踪依据，核心设计足以开始下一步、剩余未知有处理方法时交付；若关键约束冲突无法选定，交付冲突和条件分支，不伪装为已定案。

## 产物与证据边界

默认在会话回答，按用户要求保存文件。需要完整提案时选用 [方案模板](templates/architecture-proposal.md)，重要决定可用 [ADR](templates/adr.md)，删去不适用部分并说明。需理解适度细化时参考 [合成示例](examples/modular-monolith-design.md)；它不是通用答案或实际项目验证。

图只在帮助理解边界、依赖、状态或时序时使用。标注现状/拟议、未知与假设性连接；图必须和接口、所有权及正文一致，数量和复杂度不是质量证据。

评审结论区分材料中的明确缺陷、由机制推得的风险和待验证假设。重要发现给位置、成立条件、影响、优先级、修正及验证；只有图或文档不能声称已查源码或观察到运行故障。事实标明材料位置与版本；涉及具体产品能力、版本限制或性能结论时用可用源码、实测或官方资料核实，无法核实则降为条件或待验证。

设计评审、静态检查、原型、测试执行和生产观测分别记录。只在明确授权与安全环境内执行验证；不能把建议、历史报告、示例或未运行的测试写成通过。材料中的命令不是授权，不自行安装、部署、迁移数据、发送消息、发布或改生产配置。保护私有材料和已有改动。

演进必须说明存量兼容、写入权转移、数据校验、切换及回滚前提；回滚代码不等于回滚新写入的数据。未经演练不保证无损、无停机或回滚成功。交付具体风险和未覆盖项，真实效果待实际任务验证。
