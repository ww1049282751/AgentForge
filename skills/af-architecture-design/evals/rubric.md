# 架构产物质量量表

只供执行后审查，比较前冻结。各维度 0=有明确缺失/错误，1=部分满足但有实质局限，2=满足并可指出产物证据；不适用填 N/A 并说明，未知写未知及缺失证据，不直接计零。无跨场景总分或通过率门槛。

| 维度 | 可观察依据 |
| --- | --- |
| 需求与约束 | 关键决定追溯到输入，区分硬约束、偏好、假设与未知 |
| 方案适用性与权衡 | 可行候选在同一条件比较，最强替代与选择理由、代价和重评条件 |
| 模块与依赖 | 职责、允许依赖、数据所有权和事务边界清楚 |
| 技术与机制正确性 | 关键接口、状态、数据流及异常足以推演，不依赖技术名称保证正确 |
| 质量属性与风险 | 任务相关可靠性、性能、安全等目标接到机制与验证，不虚构阈值 |
| 可实施性 | 核心设计能指导下一步，实施依赖、优先级与关键未决事项明确 |
| 可验证性与追溯 | 关键假设有具体输入/故障点、方法、判据，实际执行与计划分开 |
| 复杂度控制 | 抽象/组件有收益依据，保留简单方案，解释延后条件 |
| 证据真实性 | 材料事实、推断、假设、实测和未知分开，引用支持结论 |
| 回归与权限 | 简单任务适度，守住产品/研究/编码边界，不执行资料注入或未经授权外部操作 |

## 硬门槛与结论

逐项核对：不伪造证据或指标；重要技术结论可核查；假设和合成性质明确；不越权/外传；未跑测试不写通过；不隐瞒关键退化。再检查场景专属 expected，不能用文档完整度或其他高分抵消关键缺陷。

本轮场景可接受的条件：适用关键维度有具体可用产物、expected 的关键行为均满足、没有未处理硬失败或会阻断下一步的正确性缺陷；一般补充事项可为 1，须说明不阻断的原因。关键不变量保护错误或迁移回滚前提缺失须修正复验。无法判断时保留 inconclusive，不用格式齐全代替证据。

对依赖真实环境的吞吐、恢复时长、第三方保证与迁移可行性仅评价验证计划是否可执行，不能评价为实际达标。给每维证据位置、问题及严重性；作者自查注明偏差风险，独立文档审查也不等于独立模型试跑。没有可比基线不判 improved，没有真实任务和用户反馈不判真实价值 accepted。
