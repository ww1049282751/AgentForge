# 合成输入：导出方案摘录 v0

以下是虚构设计文档，没有源码、部署或测试记录。

D1：浏览器请求网关；网关调用导出 API；导出 API 将 jobs 表的 job 记录提交，随后向队列发送 job_id。无其他投递或补偿逻辑。
D2：worker 收到消息先确认消费，再从业务库读取数据。worker 将文件写入对象存储，最后更新 jobs.status=completed。任何异常由用户重新点击导出处理。
D3：网关验证登录令牌。下载接口仅通过 URL 中的 job_id 查找文件并返回；文档没有进一步说明对象级授权。链接可能从同事的聊天记录转发获得。
D4：图中网关、API、worker 各画一个方框，没有副本数。设计者写：“有消息队列，所以消息和导出结果都不会丢失。预计平均延迟 50ms。”未给工作负载或测量。
D5：业务要求每个员工只能下载本人创建的导出。导出内容含内部业务数据。用户需要看到处理中、成功或失败的可操作状态。
