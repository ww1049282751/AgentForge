# 合成输入：报告模块迁移

M1：现有单体提供 v1 报告接口。桌面客户端不能同时升级，至少一个发布周期仍调用 v1。单体直接写 reports 和 report_items，两表通过同一事务更新。其他模块有三个只读跨表查询。
M2：想把报告计算移到独立 worker，保留提交与查询入口。新 worker 将增加任务状态和产物引用；历史 report_id 必须继续有效。没有要求所有模块拆成服务。
M3：现有数据库包含历史报告；迁移期间仍会收到新报告和修改。团队提出“先回填，再让两个系统各自双写一周，最后切路由，失败切回来”。没有定义冲突处理、删除同步、写入权或反向同步。
M4：两名维护者，只能先在测试环境演练，生产变更尚未授权。停机窗口、恢复时间和允许的数据丢失尚未确认。已有数据库备份，但从未在本任务中恢复验证。
