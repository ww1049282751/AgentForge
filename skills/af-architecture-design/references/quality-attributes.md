# 质量属性与风险

在性能、可靠性、安全、成本等目标会改变设计时读取。只覆盖本任务重要属性，避免泛化清单。

用“场景 → 期望/待确认目标 → 机制 → 验证 → 失败后果”连接要求。数字必须来自用户、现有契约或实际测量；可以提出待协商目标，明确它不是既有需求或已达结果。未知不能用零或漂亮的小数填补。

| 属性 | 有区分力的场景与设计问题 | 可用验证 |
| --- | --- | --- |
| 性能/容量 | 突发还是持续负载，读写比例、载荷、热点、排队、外部依赖和退化路径；缓存失效与一致性代价 | 在声明数据集、并发模型和环境下测分位延迟、吞吐、队列长度及瓶颈；保留方法和原始结果 |
| 可用性/恢复 | 单组件故障影响什么，超时是否传播，是否能降级、重放和恢复；备份是否满足待确认 RPO/RTO | 故障注入、重启、恢复演练与数据对账；有备份不等于已证明可恢复 |
| 一致性/并发 | 哪些不变量必须原子保证，哪里允许延迟，重复和乱序如何处理 | 并发冲突、事务中断、重复消费、迟到响应与恢复后不变量检查 |
| 安全/隔离 | 谁可执行什么动作、访问谁的数据，信任边界和敏感数据生命周期；后台任务也需携带和验证授权上下文 | 跨租户、对象级权限、权限变更、回放和审计检查；不在日志记录密钥与敏感正文 |
| 可观测性 | 如何区分业务失败、超时未知和积压，如何关联一次操作及恢复动作 | 关联标识、关键状态指标、告警与处理入口；验证故障能被发现并定位 |
| 可维护性/可测试性 | 边界是否清楚、变更会穿透哪些模块、契约与适配是否能隔离测试 | 依赖检查、契约测试和一次代表性变更追踪 |
| 成本/部署 | 团队能否运行与排障，新增组件的部署、升级、值守和退出成本 | 部署/恢复步骤演练，按已知用量建成本区间；未知价格或负载需另查，不能虚构报价 |

属性可能冲突：同步一致性增加等待与耦合，异步提高解耦但增加对账和用户状态设计，多副本提升部分故障容忍却增加协调成本。用业务后果解释取舍，选择足以满足要求的最简单机制，不把每项属性都追到极值。

安全与可靠性硬要求不能被性能总分抵消。若测量与设计假设冲突，更新有关决定、验证计划及风险，保留原观察范围。
