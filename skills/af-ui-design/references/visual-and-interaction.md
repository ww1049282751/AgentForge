# 视觉方向与交互完整性

在决定布局、视觉语言、任务流、异常状态或检查可用性时读取。只细化影响本次任务的部分，不为每个控件填写契约。

## 视觉意图落到具体选择

先确定用户此刻最需要识别、比较或操作的内容，再确定阅读顺序、主次对比和空间分组。新产品形成足够使用的 tokens：文字层级、语义色、间距、表面、边界、焦点、断点及必要动效；既有产品沿用现有命名和尺度。标出一两个体现产品个性的选择及其目的，不再造完整设计系统。

检查实际内容：中文长标题是否抢占操作区；数字、单位、日期是否能比较；过长链接如何换行；空值是否区别于零；错误文案是否说明恢复动作。视觉密度由任务和设备决定，不默认每块内容套卡片。颜色不承担唯一状态信息；字体、圆角、渐变和阴影没有一律禁止的名单，使用理由与整体一致性比偏好重要。

响应式优先保持任务：窄屏必须保留哪些字段、动作与上下文，哪些可折叠或分步；横向滚动是否真的适合二维比较。测试中文、超长内容、空数据、筛选无结果、长列表和放大文字。大屏缩成小屏、截图等比缩放或隐藏主要动作都不是充分适配。按项目支持范围覆盖深浅主题、系统减少动画偏好；不要为一个页面强加新主题。

动效用于反馈、连续性、空间关系或注意力转移，必要信息在减弱/关闭动效时仍可获得。加载反馈不虚构进度；仅有不确定进度时不展示精确百分比。

## 关键任务与状态

沿 **用户意图 → 页面/入口 → 前置条件 → 即时反馈 → 处理中 → 成功/失败 → 恢复 → 结果确认** 检查主要路径。按需用简表记录状态来源、显示信息、允许操作、下一状态与证据。

| 情境 | 应决定的事 |
| --- | --- |
| 首次进入、加载、真空数据、筛选无结果 | 区分含义，给恰当下一步；清空筛选不应伪装成创建数据 |
| 权限不足、disabled | 解释原因与获得权限或满足前提的方法；隐藏还是禁用取决于信息暴露与任务 |
| 提交、重复点击、超时 | 即时反馈和防重策略；超时可能结果未知，先查状态再决定能否重试 |
| 部分成功、部分失败 | 保留已完成对象，明确失败范围与安全重试，不能整体标绿 |
| 取消、撤销、离开返回 | 取消请求是否被接受与是否已停止分开；撤销只用于真实可逆操作；返回后如何核对权威状态 |
| 并发变更 | 显示过时或冲突信息，保留输入并重查；不能静默覆盖他人修改 |

对 Agent/异步任务界面，将连接状态、任务生命周期、取消请求结果、人工确认/审批和结果验收分别显示。连接断开不等于失败；请求被接收不等于执行完成；执行完成不等于产物合格；人工点击确认不等于运行成功。没有权威事件/接口时写“待确认”及查证动作，不制造后台能力。

关键操作契约至少说明：谁能做、作用对象、所需数据、进行中提示、成功依据、失败/未知时如何恢复。业务缺少幂等或取消接口时提出约束/需求，不假定前端禁用按钮就解决后端重复执行。

## 可访问性作为任务质量

使用语义元素、可理解标签、可见焦点和合理焦点顺序；弹层需要适当的焦点进入、退出和返回，错误与异步反馈要能被感知。检查键盘完成关键任务、触控命中区域、文本与非文本对比、颜色之外的状态线索及放大后的内容。截图只能筛查部分问题，读屏与焦点行为必须实际执行后才有通过结论。

Web 精确标准按项目要求核对 [WCAG 2.2 Quick Reference](https://www.w3.org/WAI/WCAG22/quickref/) 的相应成功准则、等级、例外和测量方式。2026-10-25 核对了该官方入口；它提供按等级和技术筛选的参考。此处方法不是完整合规审计，也不把 Web 准则自动等同于原生平台规范。
