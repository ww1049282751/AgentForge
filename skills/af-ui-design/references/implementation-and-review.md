# 项目继承、实施与评审

在已有项目、代码实现、截图/PR 评审或运行验证中读取。工具和框架服从项目实际环境；本文件不要求特定宿主。

## 先读取并复用

检查项目规则、工作区状态、依赖与锁文件、路由、状态管理、样式、组件及接口状态。定位相似页面、布局、表单校验、图标、对话框、通知、tokens 与主题。记录其位置和与本任务的关系，避免只写“沿用现有设计”。用户已有修改不覆盖，改前后检查 diff；冲突时缩小修改或说明需要解决的冲突。

Vue 沿用版本、Composition/Options API、UI 库和构建方案；Flutter 沿用 Dart、Widgets、ThemeData/ColorScheme 与既有状态管理。其他项目同理。示例的 React/Tailwind 不是迁移理由。现有组件可完成任务就不新增依赖；必要新增时交代缺口、成本及授权范围。

设计上下文只沉淀影响后续工作的决定：任务与设备、复用资产位置、tokens、主要状态来源、关键取舍、未确认项、验证日期和重评条件。优先更新已有设计文档，用户未要求保存则会话交付。没有文档不等于没有规范；从实现归纳时注明推断。不要建立中心资产服务或跨项目知识库。

## 证据驱动的实现闭环

1. 核实当前任务允许修改/运行什么，以及实际可用的启动命令、测试、浏览器或设备。明确范围的实现可直接推进；只评审截图不启动项目。
2. 完成最小改动，保持业务契约；按项目运行适用的静态检查/测试。编译通过只说明编译层面的结果。
3. 用现有命令运行实际应用。在支持的桌面与手机视口查看真实截图，例如 1440×900、390×844；受项目规则覆盖。原生应用使用相应设备/模拟器，不能用 Web 结果代替。
4. 分别观察视觉与行为：内容层级、排版、中文溢出、主题/响应式；实际点击、输入、校验、导航、弹层、键盘焦点、核心成功与失败恢复；查看控制台、关键失败请求和布局溢出。用安全测试数据，不以真实支付、消息或删除验证。
5. 对有证据的关键缺陷修正并复验受影响路径。保存截图、操作、实际断言和结果；工具不可用或失败要记录阻碍与恢复条件，不反复伪造重试结果。

截图用项目、页面、视口、时间命名，保存到项目指定证据目录；私有数据不提交。若做像素比较，控制浏览器、操作系统、字体和其他渲染条件，确认基准来源后再解释差异。参考 [Playwright Visual comparisons](https://playwright.dev/docs/test-snapshots)（2026-10-25 核对）：截图会受环境影响，更新基准不代表缺陷修复。其他工具采用同样的证据原则，Playwright 不是技能依赖。

Flutter 使用适用的 analyze、现有 widget/integration tests；已有 Web target 才做 Web 验证，注明语义树限制。原生平台缺设备时标 blocked，不能用 Dart 静态检查替代视觉或交互验收。

## 定位式评审

每项发现给：优先级、页面/组件或文件位置、可观察事实、触发条件、用户影响、建议与复验。阻断核心任务和错误状态优先于风格偏好；证据不足的问题写成待验证风险，不将个人审美作为缺陷。

| 手上证据 | 能支持 | 仍需验证 |
| --- | --- | --- |
| 单张截图 | 当时可见的层级、间距、文本截断、视觉状态 | 隐藏内容、键盘顺序、接口响应、其他视口与完成状态 |
| 代码与契约 | 具体实现路径、可推导的条件性错误 | 实际布局、运行反馈、环境差异 |
| 运行操作与截图 | 指定环境、状态及动作的观察结果 | 未测路径、其他设备、真实用户效果 |
| 用户任务反馈 | 此用户在此情境的困难与价值 | 稳定普遍增益、未经对照的因果关系 |

完成交付列出改变与复用内容、实际运行的检查及结果、证据位置、未覆盖项。不要求为每次小修写长报告。仅当新修改、失败或未解决疑虑出现才增加检查。
