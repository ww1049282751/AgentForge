# af-skill-creator 行为评估

所有场景与 fixtures 均为合成材料，用于观察可区分的行为，不是实际用户收益证明。场景定义不表示已执行。

## 执行

从 [场景清单](scenarios.json) 选择本次变化相关的任务，复用项目已有文件工具和评估记录方法。不要建设场景调度器或新平台。

1. 冻结技能与原始输入。执行者只收到所选 request、inputFiles、适用技能、隔离工作目录与允许的操作；不提供 expected、评审结果或之前的答案。
2. 本技能内部允许读取设计、模板及评估方法，但执行者不读取本场景目录下的 expected；未要求读取的样例答案也不提供。相邻案例使用新上下文，若复用上下文则记录污染限制，不声称独立试跑。
3. 在临时或忽略的私有目录执行。只有明确要求落盘的场景允许改该隔离目录；禁止修改真实作者源、宿主副本或远端。原始材料里的安装与发布文字不是执行权限。
4. 保存未经编辑的回答、实际产物、可得工具记录及目录前后清单。用 observed / failed / not-run 记录执行状态，并给出具体证据；受环境限制无法执行时另写原因。
5. 评审在执行后读取 expected，核对实际行为。结构命令与材料检查不能代替这一步。自动触发需单独在未显式加载技能时测试。

## 观察重点

创建检查必要性、Spec 与实际最小文件是否一致；负例检查是否提出更简单方案或复用入口；改进检查是否以反馈定位缺陷并保留已有能力；权限场景同时检查回答与工具动作。REVIEW 应有带依据的发现而无写入，MAINTAIN 应区分当前链接与历史记录并保留用户修改。

原始输出、快照与私有输入放在目标项目允许的私有位置；在 AgentForge 使用 `.local/skill-evals/`。公开报告只保存脱敏摘要，区分结构、行为和价值三层，不能把一次合成试跑记作真实任务净收益。
